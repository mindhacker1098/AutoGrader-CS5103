## Result on the cheating submission
`execl("./ref")`: **80 → 60**. Edge cases 10 → 0, complexity 10 → 0. The remaining 60 comes from quality metrics
(syntax, structure, modularity, memory safety, readability, originality), which judge how the code is written. Any
non-functional but tidy program earns them. Whether those should require some passing tests is a grading-policy
decision for the instructor.

## Not changed
- Copying from ChatGPT, Gemini or Claude is only detected if similar code is in `corpus/llm`. The local model cannot
  search the web, and website copies are only detected against files placed in `corpus/web`.
- LLM-suggested test inputs remain disabled in the rules (`pre_analysis.llm: false`).

## 7. Copies of the reference solution were invisible
Submission 5 (prime_number) is identical to `reference.c`, but the report said "Too little distinctive code (0
fingerprints)". The similarity check removed every fingerprint shared with the reference solution as if it were
boilerplate, so a copy of a leaked solution had nothing left to compare. Now only starter code is removed, and a match
with the reference at or above the threshold raises `suspected_copy_reference` (originality 0, hidden from students
until reviewed). Submission 5 is now flagged at similarity 1.00. In prime_number's rules the originality weight is 0,
so the flag does not change that grade; set the weight (for example 0.10) to make it count.

## 8. Website-copy detection (new)
Known web solutions can now be collected into `corpus/web` without the command line.
- **Admin:** Problems → (problem) → AI-origin corpus tab → "Find web solutions". Paste result page URLs found with a
  normal browser search, then click "Save web solutions".
- **CLI:** `python -m autograder.cli web-corpus prime_number --url <page> [--url <page> ...]`.
- **Optional automatic search:** set `BRAVE_API_KEY`, or `GOOGLE_CSE_KEY` and `GOOGLE_CSE_CX`, and use
  `--query "C program to check prime number"`. Search engines are not scraped; without a key, URLs are required.
- Only the query and the page downloads leave the server; student code never does.
- C programs inside `<pre>`, `<code>` and `<textarea>` blocks are extracted. C++, Java and Python, and output-only
  blocks, are skipped. A program is kept if it compiles in the sandbox (it does not have to match the problem's output
  wording) and is not a near-duplicate. Each file records its source URL.
- Similarity (`core/analyzers/similarity_flag.py`): the review rule is now token ≥ 0.75 and syntax tree ≥ 0.70.

Real test on prime_number:
- Two real pages (GeeksforGeeks, Programiz) gave 4 solutions; three other pages could not be downloaded and were
  reported.
- A student copy of the Programiz code with renamed variables and changed output text: token 0.81 / AST 0.74, flagged
  for review against `web:programiz_4.c`.
- An honest textbook-style solution (0.67) and a ChatGPT-style solution (0.37) were not flagged.
- The live prime_number problem now has these 4 web solutions.
- Tests: `backend/tests/unit/test_webcorpus.py` (5 tests, including a real Docker compile).

Limitation: very common short programs (prime check, add two numbers) look alike, so matches there are review flags,
not proof.

## 9. Class plagiarism scan ignored the reference solution
The Plagiarism page found 0 pairs for prime_number. `core/plagiarism/pairwise.py` removed every fingerprint shared
with `reference.c` (the same mistake as fix 7), so submissions close to the reference had almost nothing left to
compare. Only starter code is ignored now, and the reference solution is added to each scan as a comparison item
(`reference:reference.c`, shown as "instructor's reference solution"). On a copy of the live database the scan now
finds one cluster: sub 3 = reference (1.00), sub 3 vs sub 9 (0.96), sub 9 vs reference (0.96).
