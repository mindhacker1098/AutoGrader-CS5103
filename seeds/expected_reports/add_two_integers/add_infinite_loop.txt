--- Usefulness & limitations of this evaluation ---
Useful for:
  1. Grading a large lab course unattended
     Example: A CS5103 lab with 150 students submits sort.c. `npm run grade:all`
              grades every file in one run, with the same rules, the same tests
              and the same seeds, and writes one JSON and one text report per
              student. TAs only open the reports carrying a flag.
     Benefit: Hours of manual running and checking become minutes, and two
              students with the same mistake always lose the same marks.
  2. Instant feedback before the deadline
     Example: A student uploads add.c in the web UI and is told: input
              "2147483647 1", expected 2147483648, got -2147483648, because the
              sanitizer reports signed integer overflow; use long long. They fix
              it before the real submission.
     Benefit: The student gets a concrete failing input and the reason, not just
              'wrong answer', which is how people actually learn to debug.
  3. Coding-interview and hiring screens
     Example: A company gives 500 candidates the 'sort integers' task. The agent
              ranks them by correctness, edge cases (empty input,
              INT_MIN/INT_MAX), measured complexity and memory safety, with a
              per-metric explanation for every score.
     Benefit: Fast first-round filtering where every rejection can be justified
              metric by metric.
  4. Plagiarism and LLM-copy triage
     Example: Two submissions reach 0.93 similarity (threshold 0.85) after
              variables were renamed, and a third matches a solution in the LLM
              corpus. The instructor reviews those three files instead of all
              300.
     Benefit: Manual checking is limited to suspicious cases, and renaming or
              reformatting does not hide copying.
Limits of this report:
  1. Tests cannot prove correctness
     Example: A program contains `if (a == 123457 && b == -9) puts("0"); else
              printf("%lld\n", (long long)a + b);`. No hidden test, edge case or
              random trial happens to use exactly that pair, so the agent
              reports full correctness for a program that is wrong on one input.
     Fix: More trials and generators that target the program's own constants
          (read from the source) would raise the chance of hitting such
          branches, but testing can only show the presence of bugs, never
          their absence.
  2. Measured complexity depends on the inputs generated
     Example: A quicksort that always picks the first element as pivot is O(n
              log n) on the random arrays used for measurement, so the estimator
              reports O(n log n) and full marks, although it is O(n^2) on
              already-sorted input.
     Fix: Measure on several input shapes (sorted, reverse, all equal) and
          grade the worst; the cost is longer grading time.
  3. Similarity is unreliable for very short programs and for restyled LLM code
     Example: Two students independently write the same 6-line add.c. Once the
              boilerplate shared with the reference is removed, too few
              fingerprints are left, so the agent reports 'low confidence, not
              flagged': a genuine copy of a short program would also be missed.
              A student who takes an LLM solution and restructures the loops
              evades the LLM corpus.
     Fix: Treat originality as a triage flag for a human, never as proof;
          enlarge the LLM corpus with several models and prompts.
  4. Readability depends on the model, and output checking is literal
     Example: With qwen2.5-coder the agent gives a file 7/10; the same file
              under another model or Ollama version may get 6/10 (the cache
              keeps one machine reproducible, not two different setups).
              Separately, a program that prints "Sum = 12" instead of "12" is
              computed correctly but fails every test.
     Fix: Pin the model and its version in the rules and ship the LLM cache
          with the grades; state the exact output format in the problem
          statement.
